# 古文単語 学習アプリ

古文単語を「覚える → 意味を確かめる → 文中で解く」の順に学ぶ静的Webアプリです。

公開版: https://shtomi-tech.github.io/kobun-vocab-learning/

## 起動

```powershell
cd C:\Users\shtom\dev\kobun-vocab-learning
py -3 -m http.server 8062 --bind 127.0.0.1
```

`http://127.0.0.1:8062/` を開きます。JSONを読み込むため、`index.html` の直接表示は使いません。

## 現在の学習フロー

1. 4語の暗記カードを読む
2. その4語について、例文の傍線部から意味を選ぶ
3. この「覚える → 確かめる」を3ブロック行う
4. 意味確認で誤答した語をカードで確認する
5. 現代語訳を手掛かりに、例文の空欄へ入る語の基本形を選ぶ
6. 文中問題の誤答を解き直す
7. 全12語の最終チェックで80%以上を取る

進捗と途中位置はブラウザのローカルストレージに保存します。

暗記カード画面では、見出し語・意味・解説・例文をまとめて確認できます。

## 補助学習

- 全セットの通常学習で文中問題まで回答した語を、共通プールとして「意味だけ復習」の対象にします。
- 1回の出題は最大20語です。
- 正解した語は1日・3日・7日・14日後へ順に回し、誤答すると「要再確認」に戻します。
- 通常学習・意味だけ復習・誤答確認・最終チェックの履歴を、セットごとに最大500件保存します。
- 学習中はセットごとに途中位置を保存し、ホームから再開できます。
- ホームのセット選択を開くと、切り替える前に各セットの状態（未着手・学習中・要復習・最終チェック待ち・CLEAR）、文中回答済み数、要復習数、最終チェックBESTを確認できます。

## 学習目標と到達予想

ホームの語彙目標カードの上段に「学習目標」パネルがあります。

- 常時表示は「今日 n / m語」1本です。文中問題（STEP 3）へ初めて回答した語を数えます。正誤は問いません。同じ語の解き直し・意味だけ復習・最終チェックは重複して数えません。
- 「今日」の実績は、各語の初回答時刻（`units[wordId].firstAnsweredAt`。再回答では更新しません）を端末のローカル日付へ戻して集計します。この時刻を持たない既存データは、学習履歴の最古の文中回答時刻から一度だけ補完します。補完できない古い回答は、到達語数には含めますが「今日」には含めません。
- 「学習目標を設定」から〈1日の単語目標〉（1〜60語、初期値12語＝1セット）を変更できます。
- 同じカードの「このペースで学べる語」を開くと、1語＝語彙1として、7・30・90・180・365日後の理論上の学習語数と、その目標ペースで600語へ到達する予想日を表示します。いずれも目安で、収録語数を超える理論値を含みます。
- 学習目標は、通常のURLでは `localStorage` の `kobun_vocab_study_plan_v1`（`?s=` 付きは生徒IDで分離）に保存します。生徒別URLでは既存の進捗パッチと同じ経路で `studyPlanV1` としてクラウドへ同期し、アプリID・保存キー・RPCは変更しません。

新しいセットは、同じ形式のJSONを追加し、manifestへ登録します。各語には `example`、`translation`、`source`、`cloze`、`notes`（空でない解説・補足の文字列配列。1件以上必須）に加え、`exampleForm`（`"waka"` か `"prose"`）を必ず収録します。和歌には5句の表記・読み・作者・出典箇所を持つ `waka` を添えます。複数の候補例文を登録する場合は任意の `examples` に `sourceType` を付け、添付資料 → 和歌 → 古典作品の文章 → 生成した学習用作例の順で主例文を選びます。

語やセットを追加するときの作成基準は [docs/AUTHORING_STANDARD.md](docs/AUTHORING_STANDARD.md) を正本とします。例文の典拠と底本の決め方、`source` の表記、空欄の作り方、和歌のフィールド、検証手順をまとめています。採用した底本は [docs/SOURCE_EDITIONS.md](docs/SOURCE_EDITIONS.md) に記録します。

## 匿名利用・生徒別同期

通常のURLではローカル保存だけで動作します。`?s=<生徒ID>&t=<アクセストークン>`付きURLでは、`static/config.json`にSupabase設定がある場合だけ、共通の`app_students` / `app_progress`へ同期します。アプリIDは`kobun-vocab-learning`です。共有URLで使うと、同じ端末でも生徒IDごとにローカルの一時キャッシュを分離します。

生徒の登録と生徒別URLの発行は、アプリ管理ポータルの生徒共有パネルから行います。GitHub Pages公開版では、ActionsのSecretsからSupabase設定を生成します。

設定例は`static/config.example.json`です。設定がない場合も匿名利用には影響しません。
