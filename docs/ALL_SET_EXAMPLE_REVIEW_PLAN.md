## 固定する実装方針

- 既存の `example`、`translation`、`source`、`cloze`、`exampleForm` を学習画面の互換フィールドとして維持する。
- 複数候補を残す必要がある語だけ、語レコードの `examples` に `sourceType` を付ける。配列の並びではなく、アプリの優先順位で主例文を選ぶ。
- 和歌は `docs/waka-adoptions.json` を入力表とし、`node scripts/apply-waka.mjs` で反映する。散文は対象JSONを直接更新する。
- 和歌は本文、五句、読み、作者、歌集・巻・歌番号を確認する。散文は作品名・段名または章名・本文範囲・底本を確認する。
- NDL資料は `info` で公開区分と収録範囲を確認し、`search` の結果だけで決めず、必要な箇所は版面画像で照合する。
- 源氏物語は既存方針どおり底本を特定しない。これを他作品へ広げない。
- 添付資料を参照できない間は、内容・出典を推測して「添付資料由来」としない。確認できないものは `学習用作例` として残す。
- 語ID、語順、`dataVersion`、語義、進捗キーを変更しない。語義そのものの修正が必要な場合は、例文見直しとは別の変更として扱う。

## 1セットごとの作業手順

1. `docs/SET_NN_FIX_PLAN.md` を新規作成または更新し、対象語、現状の出典、候補、未確認点を列挙する。
2. 対象語のID・語義・注記・例文・空欄を控え、変更範囲を固定する。
3. 添付資料の候補が確認できる場合は最優先で照合する。確認できなければ、和歌、古典本文の順に候補を探す。
4. 採用候補をNDLの資料情報・収録範囲・検索結果・版面で確認する。確認できない候補は実出典として登録しない。
5. `docs/SOURCE_EDITIONS.md` に底本と語ごとの採用箇所を追記する。新しい底本を使う場合は底本一覧にも追加する。
6. 和歌は `docs/waka-adoptions.json` へ入力し、散文は語JSONへ反映する。`example` を変えたら、現代語訳と `cloze` も同時に見直す。
7. 形式検査、セット内の文中四択、人手による語義・訳・空欄の確認を行う。
8. 変更したセットの計画書に、採用理由、未確認事項、検証結果を記録する。

## 注意点と対策

- 添付資料が再提示された場合は、既存の和歌・本文より先に資料中の例文を再照合する。
- NDLの全文検索は関連度順で、作品名やPIDによる絞り込みが十分に効かないことがある。検索結果の採用前に資料情報と版面を確認する。
- `scripts/apply-waka.mjs` は入力表全体を適用するため、保留中の別セットの変更を意図せず作業ツリーへ戻さないよう、対象差分を確認してから実行する。
- 例文が本文に見つからない場合、無理に出典を付けず、`学習用作例` のままにする。出典欄だけ立派になる現象は、古文でも起きる。
