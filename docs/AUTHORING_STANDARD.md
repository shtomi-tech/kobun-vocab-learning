# AUTHORING_STANDARD — 語データの作成基準

> 対象: `data/set-*.json` へ語・セットを追加、または既存語の例文を差し替えるときの正本。
> 前提: 段階1〜3（`06b17bf` / `8eb7ddc` / `51ce396`）で確立した規約をまとめたもの。個別の経緯は [WAKA_PHASE1_PLAN.md](WAKA_PHASE1_PLAN.md) / [WAKA_PHASE2_PLAN.md](WAKA_PHASE2_PLAN.md) / [WAKA_PHASE3_PLAN.md](WAKA_PHASE3_PLAN.md) を参照。
> 底本の一覧と語ごとの対応は [SOURCE_EDITIONS.md](SOURCE_EDITIONS.md)。

## 0. 追加の手順

1. 例文の典拠を決める（§2）。候補が複数ある場合は、§0-1の採用順で主例文を決める。和歌にするか散文にするかを§1の基準で判断する。
2. 本文を底本から起こす（§2-2）。**日文研の和歌データベースは所在確認にだけ使い、本文の入力元にはしない。**
3. 語のJSONを組み立てる（§3〜§5）。
4. 底本を [SOURCE_EDITIONS.md](SOURCE_EDITIONS.md) の「語ごとの対応」へ追記する。
5. 差し替え・一括追加は `docs/waka-adoptions.json` に入力表を書き、`node scripts/apply-waka.mjs` で反映する。**JSONを直接手で編集しない**（再実行で巻き戻るため）。
6. §7の検証をすべて通す。

### 0-1. 例文候補の採用順

同じ語に複数の例文候補がある場合は、次の順で**主例文を1件**選ぶ。

1. 添付資料にある例文（`sourceType: "attached"`）
2. 和歌（`sourceType: "waka"`）
3. 古典作品の文章（`sourceType: "prose"`）
4. 生成した学習用作例（`sourceType: "generated"`）

和歌は、語義・文法・本文の確認ができる場合だけ候補にする。順位を満たすために、語義と合わない和歌を無理に採用しない。

既存の単一例文形式との互換性を保つため、候補は語レコードの任意フィールド `examples` に同じ形式で収録できる。各候補には `example` / `translation` / `source` / `cloze` / `exampleForm` を必須とし、和歌なら `waka` も添える。

```json
"examples": [
  {
    "sourceType": "prose",
    "example": "古典作品の本文…",
    "translation": "現代語訳…",
    "source": "作品名（段・章）",
    "cloze": "古典作品の（　）…",
    "exampleForm": "prose"
  },
  {
    "sourceType": "attached",
    "example": "添付資料の例文…",
    "translation": "現代語訳…",
    "source": "資料名",
    "cloze": "添付資料の（　）…",
    "exampleForm": "prose"
  }
]
```

`examples` の配列順ではなく `sourceType` の順位で選び、同じ種類が複数ある場合だけ配列順を使う。選ばれた候補は既存の `example` / `translation` / `source` / `cloze` / `exampleForm` として学習画面に渡される。候補未登録の語は、従来どおり語レコード直下の単一例文を使う。添付資料を確認できない場合は、添付例文や出典を推測して登録しない。

## 1. 和歌にするか散文にするか

`exampleForm` は **`"waka"` か `"prose"` を必ず明示する**（省略は検査で落ちる）。

| 語の性質 | 判断 |
|---|---|
| 心情・自然・恋・無常・時間・親族/人称語 | **和歌を優先**。万葉集・古今集に用例が多い |
| 敬語・待遇表現・皇室語彙・会話特有語 | **散文**。和歌にはほぼ現れない |
| 句型そのものが見出し語（「〇〇といふも世の常なり」など） | **散文**。実出典を当てると空欄の一意性が崩れる |
| 歌集に載るが本文が地の文（詞書） | **散文**。`source` に「（詞書）」を付ける |

和歌を無理に増やさない。語義と歌意が対応しない歌を採ると、かえって学習価値が下がる。

## 2. 典拠と底本

### 2-1. `source` の表記

| 種別 | 表記 | 例 |
|---|---|---|
| 和歌 | **歌集名のみ**（巻・番号は `waka.ref` へ） | `古今和歌集` |
| 歌集の詞書 | 歌集名＋（詞書） | `古今和歌集（詞書）` |
| 物語・日記・説話 | 作品名＋（巻・段・章） | `大鏡（太政大臣伊尹伝）` |
| 句型の学習用作例 | `学習用作例` | — |

`出典未詳` / `学習用例文` / `単語解説` は**使わない**（検査で落ちる）。出典が特定できないなら作例として作り直し、`学習用作例` と明示する。実出典を装わないこと。

### 2-2. 本文の調達元

- 本文は **NDLデジタルコレクションで「インターネット公開（保護期間満了）」と表示される資料**から起こす。申請・許諾とも不要。
- 採用前に `dl.ndl.go.jp/pid/<PID>` の書誌ページで公開範囲と巻次を必ず確認する。**書名だけで判断しない**（過去に解説巻・別巻を誤って底本にした事例がある）。
- 日文研の和歌データベースは編集著作物として権利を主張しているため、**検索（所在確認）にのみ使う**。本文の転記元にしない。
- 決めた底本は [SOURCE_EDITIONS.md](SOURCE_EDITIONS.md) に記録する。同じ歌集の語は同じ底本で揃える。
- **例外: 源氏物語は底本を特定しない。** 現在のデータが依拠する大島本系の校訂本文と、NDLでインターネット公開されている活字翻刻の本文系統が一致しないため。詳細と根拠は [SOURCE_EDITIONS.md](SOURCE_EDITIONS.md) の「源氏物語は底本を特定しない」を見る。源氏物語の語では `source` に作品名と帖名だけを書き、`SOURCE_EDITIONS.md` の底本欄は「—（底本を特定しない）」とする。この例外を他の作品へ広げない。

## 3. 共通フィールド

必須: `id` / `headword` / `kanji` / `meanings` / `notes` / `example` / `translation` / `source` / `cloze` / `exampleForm`

- `headword` は歴史的仮名遣い。`notes` は1件以上、空文字不可。
- `id` は全セットで一意（`kvNN-XXX`）。`meta.count` と語数を一致させ、`meta.dataVersion` は**据え置く**（上げると最終チェックBESTと途中位置が消える）。
- `translation` は現代語訳。**`meanings` の語義と噛み合っているかを必ず確認する**。歌集の部立（釈教・恋・秋など）は語義の手掛かりになる。

## 4. `cloze`（空欄）の作り方

- 空欄は `（　）` ちょうど1つ。`example` の**連続した1スパン**を置き換える。
- **答えが `example` の他の場所に出ていないこと。** 出ていると語義を知らずに正答できる。
  - 例外は語法上の反復のみ（「かつ〜かつ〜」）。その場合は `check-data.mjs` の `answerRepeatAllowedById` に理由コメント付きで登録する。
  - 空欄が1文字の語は検査の対象外（偶然一致が多いため）。**人手で見ること。**
- 別表記での露出も避ける（見出し語「みゆき【行幸・御幸】」で空欄が「御幸」、本文に「行幸」が見えている等）。
- 空欄に助動詞・接続助詞などの付属語を含めない（`けり` `ば` `む` `て` 等）。見出し語の一部である場合だけ `headwordOwnedSuffixesById` に登録する。
- 和歌では**空欄が1つの句をまたがない**こと。

## 5. 和歌（`exampleForm: "waka"`）の `waka`

```json
"waka": {
  "phrases": ["紫草の", "にほへる妹を", "憎くあらば", "人妻ゆゑに", "我恋ひめやも"],
  "reading": ["むらさきの", "にほへるいもを", "にくくあらば", "ひとづまゆゑに", "われこひめやも"],
  "author": "大海人皇子",
  "ref": { "collection": "万葉集", "book": "巻一", "number": 21 }
}
```

- `phrases`: 5要素。**`phrases.join("")` が `example` と完全一致**すること。改行は入れない（表示側が句区切りを作る）。
- `reading`: 5要素、ひらがなのみ、**歴史的仮名遣い**（`おもへば` であって `おもえば` ではない）。小書きの拗音は使わない。各句のモーラ数は 5/7/5/7/7 に対し **±1 まで**（字余り・字足らず）。
- `author`: 必須。不明なら `よみ人しらず`。
- `ref.collection`: `source` と完全一致させる。
- `ref.book`: 勅撰集は**「巻＋部立」**（`巻十四・恋歌四`）。部立を持たない万葉集は巻のみ（`巻三`）。
- `ref.number`: 歌番号。**任意**。底本が通し番号を印刷している場合だけ、その番号に揃えて入れる。
  『和歌三代集』『万葉集古義』『拾遺和歌集』下など、本文と作者は載せても通し番号を持たない版が多く、
  番号を必須にすると確認できる和歌まで採れなくなるため。番号がない歌は、学習画面には巻・部立だけが出る。
  **番号を推測で埋めない。**
- 和歌本文に句読点（`、` `。`）を入れない。

## 6. 出題への配慮

- **同一セット内に意味の近い語を集めすぎない。** 選択肢生成は意味重複ガードを先に通すため、親族語・人称語のように意味が近い語が固まると安全な誤答候補が枯れ、音数リーク対策のフォールバックが働く。
- 和歌の文中問題は空欄の音数が確定する。見出し語のモーラ数が近い語が同じセットにあると誤答が作りやすい。
- 例文は空欄の前後に語義を判断できる手掛かりを残す。文脈を削りすぎない（対句・呼応表現は切らない）。

## 7. 検証

追加・変更後に次をすべて実行する。

```bash
node --check static/mode-vocab.js
node --check static/meaning-guard.js
node scripts/check-data.mjs
node scripts/check-waka-data.mjs
node scripts/check-waka-choices.mjs
node scripts/check-waka-display.mjs
node scripts/check-context-choices.mjs
node scripts/check-srs.cjs
```

### 自動で守られること

`exampleForm` の必須と値／`waka` 一式の構造・モーラ数・歴史的仮名遣い・句またぎ／`phrases` と `example` の一致／`source` の書式（和歌は括弧なし、旧表記の禁止）／`ref` の必須と部立／`cloze` の空欄数・連続スパン・付属語・答えの露出（2文字以上）／`id` の一意性／`meta` の整合

### 人手で守ること

- 本文が底本と一致していること（字面・仮名遣い）。
- `translation` が `meanings` と噛み合っていること。
- 1文字空欄の答えの露出。
- 掛詞の一方を空欄にしていないこと（基本形が一意に決まること）。
- 歌集・作者・歌番号が正しいこと。
- UIに関わる変更を伴う場合は実ブラウザで確認（カード・文中問題・320px幅・コンソールエラー）。
