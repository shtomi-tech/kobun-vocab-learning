# 古文単語例文 品質評価ルーブリック

> 最終更新: 2026-09-07 ／ 対象: `data/set-*.json` 50セット・600語の主例文
> データ形式と典拠の正本は [AUTHORING_STANDARD.md](AUTHORING_STANDARD.md)、底本と語ごとの採用箇所の正本は [SOURCE_EDITIONS.md](SOURCE_EDITIONS.md)、照合手順は [NDL_COLLATION.md](NDL_COLLATION.md)、これまでの監査記録は [ALL_SET_EXAMPLE_REVIEW_PLAN.md](ALL_SET_EXAMPLE_REVIEW_PLAN.md)。
> 本ルーブリックはそれらを置き換えるものではなく、人手レビューの判定を揃え、判定結果を台帳へ戻すためのものである。

## 1. 目的と適用範囲

各語の主例文について、次の二つを分けて判定する。

1. **教材として採用してよいか**（本文・語義・訳・出典に誤りがないか）
2. **学習問題として機能するか**（対象語を学べ、文中問題の正答が一意に決まるか）

例文は、作問の都合で新しく作るのではなく、**実在する古典作品で対象語が実際に使われている箇所を採ることを原則**とする。実例には、その語が用いられた時代・文体・係り受け・共起表現を同時に学べる価値がある。学習用作例は、句型そのものが見出し語である、適切な実例を確認できないなど、実例採用が難しい場合の例外とする。

対象フィールドは `headword` / `kanji` / `meanings` / `notes` / `example` / `translation` / `source` / `cloze` / `exampleForm`。`examples` や `waka` がある場合はそれらも同時に見る。**主例文を直したら `examples` 候補側の同じ値も直す**（片方だけ直すと候補と食い違う）。

### 1-1. このルーブリックで判定しないもの

判定の範囲を混ぜないため、次は例文品質の点数に含めず、見つけたら「別課題」として記録だけ残す。

| 範囲外 | 理由 | 実例 |
| --- | --- | --- |
| 見出し語・`kanji`・`meanings` の当否 | 進捗キーに関わり、変更は例文監査と別の作業になる | `kv30-349` あきれる（古語形は あきる）、`kv38-447` かまくて（辞書見出しは かまへて）、`kv22-259` ずちなし／本文は すぢなし |
| セット構成・語の選定・意味重複ガード | 出題側の設計。`static/meaning-guard.js` と `AUTHORING_STANDARD` §6 の領分 | `kv31-362` なやむ ／ `kv31-363` なやまし の同時出題抑止 |
| UI・表示・SRS | `DESIGN.md` と UI 検査の領分 | 和歌の巻・部立表示 |

### 2-2. レビューで見落とさないこと

- 実在作品名が書かれているだけで本文確認済みとみなさない。**`source` の見た目と証拠段階は一致していない。**「（添付資料）」の但し書きは第21〜28セットの運用で、第29セット以降は同じ状態でも表記されていない。
- 語義と用法の合う実在古典の確認済み本文を、学習用作例より優先する。
- 添付資料由来の例文と、底本まで照合した例文を同じ証拠段階として扱わない。
- 短すぎる例文は文脈不足、長すぎる例文は認知負荷を個別に判定する。散文は必要な文脈を保った最短の連続本文を採り、原則60字以内に収める。
- 同一本文の共有は直ちに重複不良とせず、各空欄が別の学習目標として機能するかを見る。**共有している語どうしで訳が食い違っていないかも見る。**
- 1文字空欄は自動検査だけでは答えの露出を防げないため、必ず目視する。

## 3. 採点前の必須ゲート

以下のどれか一つでも該当した例文は、点数にかかわらず **不合格（BLOCKED）** とする。修正または根拠確認が終わるまで教材として採用しない。

| コード | 必須ゲート | 不合格となる状態 |
| --- | --- | --- |
| G1 | 出典の真正性 | 実出典を名乗るのに**台帳に記録がない**。台帳の記録と本文・作品・巻段が食い違う。確認結果が別作品を指している。異なる版の本文を合成している |
| G2 | 対象語の同定 | 例文中の語形が見出し語の活用形・表記・語彙素に属さない。同形異義語や別語を例にしている |
| G3 | 採用語義の一致 | 例文中の意味が `meanings` のいずれにも該当しない、または別の語義として読むほうが自然である |
| G4 | 本文と訳の整合 | 主語・敬意の方向・否定・呼応・時制・係り受けなどを取り違え、学習対象の意味が変わる誤訳がある |
| G5 | 空欄の復元可能性 | `cloze` に対象語形を戻しても `example` を復元できない。空欄が対象語以外を含む、活用語尾を空欄の外に残す、または和歌で句をまたぐ |
| G6 | 正答の一意性 | 同じセットの選択肢候補に、文法・語義・文脈上、同等に成立する別解がある |
| G7 | 実例優先と作例の表示 | 語義・用法の合う**確認済みの**実例があるのに、理由なく作例を主例文にしている。または生成・編集した例文を古典作品の実例のように表示している |
| G8 | 本文の時代整合 | 実出典を名乗る本文に、現代語・後世語・現代語法が混じる。古典文法として成立しない形になっている |
| G9 | 過剰な長さ | 散文が90字を超え、**かつ**対象語の解釈に不要な文・描写を含み、**かつ**短縮できない理由が記録されていない |

### 3-1. ゲートにしないもの

次はゲート違反ではなく、D（出典・典拠の透明性）などの減点として扱う。ゲートにすると、方針上許容している状態まで一律に採用不可になり、判定が使えなくなる。

- 底本を確定していない（台帳に「底本未確定」と記録されている）こと。第30〜50セットと `kv05-055` の145語、源氏物語121語がこれに当たる。
- 実例へ差し替えられる可能性はあるが、候補の本文・作品をまだ確定できていないこと（`ALL_SET_EXAMPLE_REVIEW_PLAN.md` の据え置き語）。
- 90字超でも、短縮すると係り受け・対句・呼応が切れる理由を記録してあること。

### 3-2. 証拠段階の判定

| 段階 | 台帳（`SOURCE_EDITIONS.md`）の記録 | レビュー上の扱い |
| --- | --- | --- |
| E3 | 底本の書名と採用箇所（帖・巻・段＋コマ／頁）まで記録され、版面で照合済み | 実出典の合格根拠にできる。D=3 |
| E2 | 本文確認資料（PID）や校訂本文で本文・語義を確認済み。固定底本は定めない（源氏物語の方針例外を含む） | 原則合格。D=2。版の扱いを記録する |
| E1 | 台帳に記録はあるが、作品名の根拠が添付資料だけで、一致する本文を持つ資料を確定できていない | D=1。「底本未確定」と台帳に明記されていることが条件 |
| E0 | 台帳に記録がない、推測、記録と本文が食い違う | 実出典としては G1 違反。作例なら `学習用作例` と明示する |

`学習用作例` は、出典を装わず古文として自然であっても、実在古典からの用例と同等には評価しない。採用する場合は、実例にできない理由（句型、検索困難、語義不一致、本文未確定など）を台帳とレビュー記録に残す。適切な実例候補を確認できた時点で、原則として差し替え対象にする。

## 4. 評価ルーブリック

必須ゲートをすべて通過した例文を、8観点・各0〜3点、計24点で評価する。

### A. 対象語・採用語義の明確さ

| 点 | 判定基準 |
| ---: | --- |
| 3 | 対象語形が明確で、`meanings` の特定の語義を自然かつ代表的に示す。多義語では採用語義を特定できる |
| 2 | 語義は正しいが、前後の補足や訳を見ないと採用語義がやや判別しにくい |
| 1 | 語義との関係が弱い、特殊用法に偏る、または複数語義のどれを示すか曖昧である |
| 0 | 語形または語義が誤っている（G2/G3） |

### B. 古文本文・文法の正確さ

| 点 | 判定基準 |
| ---: | --- |
| 3 | 古典本文として文法・語法・歴史的仮名遣いが正確。引用範囲も一続きで、正規化がある場合は原文と区別されている |
| 2 | 学習上の問題はないが、新字体化・踊り字展開・句読点・鉤括弧・補足表記の方針が記録から分かりにくい |
| 1 | 意味は取れるが、不自然な作例、文の切り出しによる係り受け不足、補足の表記ゆれがある |
| 0 | 文が成立しない、現代語・後世語が混じる、本文を合成している（G1/G8） |

助動詞の接続、係り結び、並立の助詞は機械的に当てて確認する。過去に `え聞きざりけり`（未然形接続違反）、`髭切が、あらぬ太刀が`（並立は「か」）が見つかっている。

### C. 現代語訳の正確さ

| 点 | 判定基準 |
| ---: | --- |
| 3 | 対象語の採用語義、主語・目的語、敬意の方向、否定、呼応、時制、文脈を過不足なく訳す。学習者が本文と対応づけやすい |
| 2 | 大意と対象語義は正しいが、意訳や補足がやや多い、または対応関係が少し見えにくい |
| 1 | 対象語義は保つが、本文にない内容、重要語の訳し落とし、重言、不自然な現代語がある |
| 0 | 対象語義や文の構造を誤って伝える（G4） |

訳に文脈補足を加える場合は丸括弧等で本文外の補いと分かるようにする（`（知的で）おもしろい`）。本文にない人物・行為を無表示で足さない。同じ本文を共有する語は、訳を突き合わせて食い違いを残さない。

### D. 出典・典拠の透明性

| 点 | 判定基準 |
| ---: | --- |
| 3 | E3。対象語・採用語義を含む**実在古典の本文**で、底本・採用箇所が台帳から追跡できる。和歌は作者・巻・部立・（確認できた場合の）歌番号が整合する |
| 2 | E2。実出典の本文と語義を確認できるが、固定底本を定めない、または巻段・採用箇所・版の記録の一部が不足する |
| 1 | E1。作品名の根拠が添付資料だけで底本未確定、またはやむを得ない理由を記録した `学習用作例` |
| 0 | E0。台帳に記録のない実出典、誤った作品・巻段、作例の偽装（G1/G7） |

`source` は学習者に見える欄なので、**作業用の情報を残さない**。コマ番号（`canvas100`）、頁（`p.109`）、叢書の輯次、版本名は台帳側に書く。表記は `AUTHORING_STANDARD` §2-1 に従う（作品名＋（巻・段・章）、段番号は漢数字、和歌は歌集名のみ）。

有名作品名が付いていることは D の加点根拠にならない。対象語がその語義・語形で現れる箇所を、実際の本文で確認できることを評価する。

### E. 文脈の十分さ・例文の焦点

| 点 | 判定基準 |
| ---: | --- |
| 3 | 必要な文脈を保った簡潔な例文。散文は原則15〜40字で、対象語の意味を判断する手掛かりが十分にある |
| 2 | 学習には使える。散文は41〜60字、または14字以下でも文法・語義・正答一意性に必要な手掛かりが揃う |
| 1 | 散文が61〜90字で短縮余地がある、または短すぎて訳や暗記に頼らないと語義を判断しにくい。固有名詞・難語・省略が対象語以上に難しい場合も含む |
| 0 | 散文が90字を超えて不要部分を含む、文脈不足で別解が成立する、または文意を確定できない（G6/G9） |

文字数は機械的な切断位置ではなく、レビューを揃えるための基準とする。散文は**15〜40字を推奨、60字を通常上限、90字を要判断**とする。61字以上なら、対象語の語義判定に必要な箇所だけを、底本上で連続する本文として切り出せないか確認する。省略箇所をつないで一つの引用にしたり、原文にない語を補って本文を作ったりしてはならない。短縮できない場合は、その理由を台帳の該当セット節に書く。

添付資料由来の例文は、資料が傍線を引いている範囲を保つ。短縮のために傍線位置と空欄の対応を崩さない。

和歌は一首全体と五句構造に教材価値があるため、この文字数基準をそのまま適用しない。詞書や前後の散文まで含める場合は、散文部分だけを必要最小限にする。

### F. クローズ問題の妥当性

| 点 | 判定基準 |
| ---: | --- |
| 3 | 空欄が対象語形の連続1スパンだけを隠し、前後から品詞・活用・語義を判断できる。基本形を選ぶ学習課題として適切である |
| 2 | 復元は一意だが、活用形と基本形の隔たりが大きい、または手掛かりが一種類に偏る |
| 1 | 答えが本文の別位置や別表記で見える、1文字空欄の目視根拠がない、音数・固有表現だけで解ける |
| 0 | 復元不能、付属語まで隠す、活用語尾を空欄の外に残す、別解が成立する、和歌で句をまたぐ（G5/G6） |

同じセット内の安全な誤答候補を実際に各 `cloze` へ入れ、文として成立しないことまで確認する。`check-set-choices.mjs --pairs` の通過だけを一意性の証明にしない。1文字空欄で答えが他所に字として現れる場合は、語義の手掛かりにならないことを確かめ、例外として記録する（`kv48-568` の「手」／「磐手の野辺」）。

### G. 認知負荷・学習者への配慮

| 点 | 判定基準 |
| ---: | --- |
| 3 | 対象語以外の難語・敬語・省略・固有名詞が必要最小限で、注記または訳により自力で理解できる |
| 2 | 軽い負荷はあるが、対象語の学習を妨げない |
| 1 | 未習語や複雑な文法が多く、対象語より周辺要素の解読が主課題になっている |
| 0 | 対象学習者が例文から対象語を学ぶことが実質的にできない |

### H. 教材価値・代表性

| 点 | 判定基準 |
| ---: | --- |
| 3 | 対象語の典型的な用法・構文・コロケーションを示し、例文と訳を一組で覚える価値が高い |
| 2 | 正確で使用可能だが、用法の代表性または記憶への残りやすさが標準的である |
| 1 | 正しいものの偶発的・特殊な用法で、同程度の根拠を持つより良い候補がある |
| 0 | 誤学習を招く、または例文としての学習価値がない |

同じ本文を複数語で共有する場合は、各語について H を別々に採点する。本文が同じでも、空欄位置・採用語義・訳の焦点が異なり、それぞれに教材価値があれば重複だけを理由に減点しない。

### W. 和歌の追加確認（`exampleForm: "waka"` のみ）

観点の点数とは別に、次を Pass / Fail で記録する。1件でも Fail なら B または D を減点する。

| コード | 確認 |
| --- | --- |
| W1 | `phrases` 5要素の連結が `example` と完全一致し、空欄が句をまたがない |
| W2 | `reading` が歴史的仮名遣いで、各句のモーラが 5/7/5/7/7 ±1 に収まる |
| W3 | `author` が底本の表記と一致する（不明なら `よみ人しらず`） |
| W4 | `ref.book` が勅撰集なら「巻＋部立」、万葉集なら巻のみ。`ref.collection` が `source` と一致する |
| W5 | `ref.number` は底本が通し番号を印刷している場合だけ入れる。**推測で埋めない**（`AUTHORING_STANDARD` §5 で任意化済み） |
| W6 | 歌意と `meanings` が対応する。掛詞の一方だけを空欄にしていない。学習例文としての調子が語義の説明に向く |

## 5. 総合判定

| 総得点 | 判定 | 扱い |
| ---: | --- | --- |
| 22〜24 | A: 優良 | そのまま採用できる。将来の模範例にできる |
| 18〜21 | B: 合格 | 採用できる。軽微な改善候補は記録する |
| 13〜17 | C: 要改善 | 誤りとは限らないが、教材として弱い。改善計画へ入れる |
| 0〜12 | D: 不合格 | 差し替えまたは大幅修正が必要 |
| ゲート違反 | BLOCKED | 得点を付けても採用不可。根拠確認または修正を優先する |

### 5-1. 合格条件

総得点だけで弱点を相殺しないため、採用には次のすべてを要求する。

- 必須ゲート G1〜G9 をすべて通過
- 総得点18点以上
- A・B・C・E・F の各観点が2点以上
- D は1点以上（＝証拠段階 E1 以上で、台帳に状態が記録されている）
- **総合A（優良）は D が2点以上（E2 以上）の語に限る。** 底本未確定のまま A 判定にしない
- 正答一意性を人手で確認済み
- 和歌は W1〜W6 をすべて Pass
- 作例なら `source: "学習用作例"` と表示し、実例にできない理由を記録する
- `学習用作例` は原則として総合判定 C（要改善）を上限とする。ただし、句型そのものが見出し語で、実例化すると空欄の一意性が崩れるなど、`AUTHORING_STANDARD` §1 が認める明確な例外は、理由を記録したうえで D=1 のまま B とできる

### 5-2. 典拠ランク（採否とは別に記録する）

採否の判定と、典拠がどこまで固まったかは別に追う。採用済みでも典拠は昇格させていく。

| ランク | 条件 | 次の一手 |
| --- | --- | --- |
| 照合済み | D=3（E3） | 維持。台帳の記載を保つ |
| 確認済み | D=2（E2） | 採用箇所・版の記録を補い、可能なら E3 へ |
| 要昇格 | D=1（E1・底本未確定） | 一致する本文を持つ PDM 資料を探す。見つからない間は台帳に「底本未確定」と明記 |
| 未記録 | D=0（E0） | 採用不可。台帳へ記録するか、`学習用作例` へ戻す |

## 7. レビュー手順

### 7-1. 1語ごとの確認順

1. `id`、見出し語、漢字、`meanings`、`notes` を読む。
2. `example` の対象語形を同定し、活用形・語義・品詞を記録する。
3. `translation` を見ずに本文を解釈し、その後で訳と照合する。
4. **台帳の語ごとの対応を引き、底本欄から証拠段階（E0〜E3）を決める。** 実出典なのに記録がなければ、そこで G1 違反として止める。
5. 実出典なら、必要に応じて `SOURCE_EDITIONS.md` と底本・正本で作品、箇所、字面を確認する（`node scripts/ndl.mjs info|search|image`、手順は `NDL_COLLATION.md`）。
6. §6 の型を当てる。特に現代語混入・接続・呼応は本文だけで判定できる。
7. 散文の文字数を確認し、60字超なら不要部分を除いた連続本文へ短縮できないか検討する。
8. `cloze` に隠された文字列を戻し、`example` が完全復元されることを確認する。
9. 同じセットの誤答候補を入れ、別解が成立しないことを確認する。
10. 同一本文を共有する語があれば、訳と空欄の役割分担をまとめて確認する。
11. 必須ゲートを判定してから、A〜H（和歌は W も）を採点する。
12. 問題があれば、事実・根拠・学習上の影響・必要な修正を記録する。

| 項目 | 記録内容 |

## 8. 修正を反映するときの規則

- **JSON を直接手で編集しない。** 再実行可能なスクリプトで、値の文字列だけを置換する（実績: `scripts/fix-example-quality.mjs` / `fix-example-quality-3.mjs` / `replace-generated-examples.mjs`）。和歌は `docs/waka-adoptions.json` を入力表にし、`node scripts/apply-waka.mjs` で反映する。
- `example` を変えたら `translation` と `cloze` を同時に見直し、`examples` 候補側の同じ値もまとめて置換する。
- 変更しないもの: `id`、語順、`headword`、`kanji`、`meanings`、`notes`、`meta.dataVersion`、進捗キー。語義・見出し語の修正は別作業として立てる。
- `apply-waka.mjs` は入力表全体を適用する。**実行前に入力表と現行データを突き合わせる**（過去に11語18フィールドが旧値へ巻き戻った）。
- 反映後、適用前後の全600語を突き合わせ、意図した語だけが変わったことを確認する。
- 典拠を確認したら `SOURCE_EDITIONS.md` の語ごとの対応（採用箇所・底本欄）と、必要なら底本一覧を更新する。**台帳を更新しない修正は証拠段階を E0 に戻す。**
- 判定結果と据え置いた理由は `ALL_SET_EXAMPLE_REVIEW_PLAN.md` の追補として残す。会話だけに置かない。

## 9. 自動検査と人手検査の境界

### 自動検査で確認すること

- 必須フィールド、ID・件数・`meta` の整合
- 空欄が1個で、例文の連続1スパンを置換すること
- 2文字以上の答えが例文中で重複露出しないこと（例外は `check-data.mjs` の `answerRepeatAllowedById`）
- 付属語を空欄へ不適切に含めていないこと（例外は `headwordOwnedSuffixesById`）
- 和歌の5句、読み、モーラ、句またぎ、`ref` の構造
- `source` の書式（和歌は括弧なし、`出典未詳`／`学習用例文`／`単語解説` の禁止）
- 例文候補の選択順（attached ＞ waka ＞ prose ＞ generated）
- 同じセットから四択候補を構成できること

### 自動検査では確認できないこと

- 本文・作品・巻段・作者が実際の底本と一致するか（**台帳の底本欄は検査対象外**）
- 現代語・後世語の混入、助動詞の接続、呼応表現の成否
- 学習用作例より優先して採れる、語義・用法の合う実在古典の用例がないか
- 例文中の語形が見出し語の採用語義に属するか
- 現代語訳が本文・敬語・呼応・文脈を正しく伝えるか。同一本文を共有する語の訳が揃っているか
- 別の選択肢を入れても文法・意味上成立しないか
- 1文字空欄（29語）で答えが露出・推測可能になっていないか
- 例文の長さが学習に適切か（文字数の検査はない）
- 掛詞、同音異義、異文、編集補足が誤解を生まないか
