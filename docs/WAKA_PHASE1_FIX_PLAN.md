## 1. 修正項目

### 1-1. `waka.reading` の仮名遣い統一（優先度: 高）

3か所が現代仮名遣いになっており、同一データ内で歴史的仮名遣い（`たまのをよ` / `ながらへば` / `わをめさましを`）と混在している。

| ファイル | 語ID | 現状 | 修正後 |
|---|---|---|---|
| `data/set-03.json` | kv03-026 | `かれぬとおもえば` | `かれぬとおもへば` |
| `data/set-08.json` | kv08-090 | `おおきみは` | `おほきみは` |
| `data/set-09.json` | kv09-106 | `きのうもきょうも` | `きのふもけふも` |

- モーラ数は 8／5／7 で修正前後とも変わらないため、既存の検証は通ったままになる（確認済み）。
- 他の27句は歴史的仮名遣いとして問題なし（`さかえし`・`よわり`・`はは` などは両仮名遣いで同形）。
- `example` / `cloze` / `translation` / 表示には一切影響しない。`reading` はUIに出力していないため、この項目にブラウザ確認は不要。

### 1-2. 仮名遣いの規約を明文化して再発を防ぐ（優先度: 高）

1-1 は「`reading` が何の仮名遣いか」がどこにも書かれていないために起きた。値を直すだけでは段階2で必ず再発するので、規約を1か所に固定する。

- `README.md` のデータ説明に、`waka.reading` は歴史的仮名遣いで書く旨を1文追加する。
- `WAKA_PHASE1_PLAN.md` の §2 の `reading` の説明にも同じ規約を明記する。

### 1-3. 検証で拗音を弾く（優先度: 中／1-2の機械的な裏付け）

歴史的仮名遣いの和歌本文に小書きの拗音は原則現れない。`check-data.mjs` の `validateWaka` に次の検査を足すと、`きょう` 型の現代仮名遣いを機械的に検出できる。

- `waka.reading` の各句が `/[ゃゅょぁぃぅぇぉ]/` を含む場合はエラー。
- これに伴い `countMora` の小書き除外は不要になるが、**削除しない**。将来この規約を緩めたときに音数計算が静かに壊れるのを防ぐため、保険として残す。
- 限界: `おもえば` 型（拗音を含まない現代仮名遣い）は検出できない。ここは 1-2 の規約とレビューで担保する。

### 1-4. `check-waka-phase1.mjs` の縮小（優先度: 中／論点B）

- 残す: 「`exampleForm === "waka"` が6件ちょうど」「その6件のIDが期待集合と一致」。
- 落とす: `phrases` / `reading` / `author` の値の複製と `deepEqual`。`phrases.join("") === example` は `check-data.mjs` が既に検証している。
- 効果: 1-1 のような読みの修正時に、テスト側を同時に書き換える必要がなくなる。

### 1-5. CIへの登録（優先度: 中／論点C）

- `.github/workflows/pages.yml` の「Check data and SRS」ステップに以下を追加する。
  - `node scripts/check-waka-phase1.mjs`
  - `node scripts/check-waka-display.mjs`
- 追加位置は `node scripts/check-data.mjs` の直後（データ検証の並びに揃える）。
- `check-context-choices.mjs` の未登録は今回の変更以前からの穴なので、本計画では触れず報告に留める。

### 1-6. 既知の穴と未確定事項の記録（優先度: 低／論点D）

`WAKA_PHASE1_PLAN.md` に「段階1完了時点の既知の穴」節を追加し、次の2件を残す。

- **音数リーク**: 和歌の空欄は音数が確定するため、語義を知らなくても選択肢の音数で正答できる。対象は6語で実害は限定的。対策は段階2で `choiceSet` に同音数の誤答選択肢生成として入れる。
- **`吾を`／`我を` の読み**: `わを` として確定させたが、伝本により `あれを` の可能性がある。段階2で本文校訂を行う際に再確認する。`あれを` が正しい場合、kv09-106 の結句は8音（字余り）となり許容範囲内なので、検証は通ったまま値だけ変わる。
