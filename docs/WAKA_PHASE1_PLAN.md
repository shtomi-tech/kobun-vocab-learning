## 2. データモデル

既存キーの意味は変えず、和歌の語にだけ任意キーを足す。`exampleForm` 省略時は `"prose"` とみなすため、既存162語は無変更で通る。

```json
{
  "example": "玉の緒よ絶えなば絶えねながらへば忍ぶることの弱りもぞする",
  "cloze": "（　）よ絶えなば絶えねながらへば忍ぶることの弱りもぞする",
  "source": "新古今和歌集",
  "exampleForm": "waka",
  "waka": {
    "phrases": ["玉の緒よ", "絶えなば絶えね", "ながらへば", "忍ぶることの", "弱りもぞする"],
    "reading": ["たまのをよ", "たえなばたえね", "ながらへば", "しのぶることの", "よわりもぞする"],
    "author": "式子内親王"
  }
}
```

設計上の要点:

- **`example` は必ず `phrases.join("")` と一致させる。** 改行は表示側の責務にする。`example` に改行文字を入れると [check-data.mjs:35](../scripts/check-data.mjs:35) の「cloze は example の連続1スパン」という不変条件と `cloze` 生成が壊れる。
- **`reading` を必須にする。** `phrases` は漢字仮名交じりなのでモーラ数を機械検査できない。句ごとの読みを持たせて初めて 5/7/5/7/7 の検証が成立し、段階2の同音数選択肢生成にも再利用できる。読みは歴史的仮名遣いで記載し、現代仮名遣いには直さない。
- `author` は必須。不明な場合は `"よみ人しらず"`。
- `ref`（歌集内の部立・歌番号）は**段階1では持たせない**。番号は伝本により揺れ、一次情報の確認が必要なため段階2へ送る。
- `rhetoric`（掛詞・枕詞）はフィールドとして予約するが段階1では書かない。既存の `notes` と役割が重複するため、`rhetoric` に一本化する分担は段階2で決める。

## 3. 検証（`scripts/check-data.mjs` の拡張）

既存チェックの後段に、和歌語だけを対象とする検査を追加する。

1. `exampleForm` があるなら `"waka"` か `"prose"` のいずれか。
2. `exampleForm === "waka"` のとき `waka` オブジェクトが必須。逆に `waka` があって `exampleForm !== "waka"` ならエラー。
3. `phrases` は5要素、各要素が空でない文字列、`phrases.join("") === example`。
4. `reading` は5要素、ひらがなのみ（`/^[ぁ-んー]+$/`）。歴史的仮名遣いで記載し、小書きの拗音を含めない。
5. 各句のモーラ数が `[5, 7, 5, 7, 7]` に対し **±1 まで許容**（字余り・字足らず）。拗音の小書き仮名（`ゃゅょぁぃぅぇぉ`）はモーラに数えない。
   - 実データで kv03-026 の結句「かれぬと思へば」が8音、kv08-090 の結句「絶ゆる日あらめや」が8音のため、この許容幅は必須。
6. 和歌本文に句読点（`、` `。`）を含まない。
7. **空欄が句をまたがない**。`cloze` の空欄位置から `phrases` 上の開始句・終了句を求め、一致すること。またぐ和歌は段階1では採用しない（表示分岐を増やさないため）。
8. `author` が空でない文字列。

モーラ計数は小さなヘルパー（`countMora(reading)`）として `check-data.mjs` 内に置く。段階2でスクリプトが増えたら共通モジュールへ切り出す。
