## 2. 収集・反映のパイプライン

### 2-0. テキストの調達方針（論点A・確定済み）

**日文研の和歌データベースは「どの歌にこの語が出るか」を探すためだけに使い、リポジトリへ入れる本文はNDLデジタルコレクションの保護期間満了資料から起こす。**

根拠として確認した利用条件は次のとおり（2026-08-24 時点）。

| 提供元 | 本文テキストの再利用 | 本計画での扱い |
|---|---|---|
| 日文研 和歌データベース | サイトポリシーで、コンテンツおよび**編集著作物**の著作権を日文研が保持すると明示。私的使用・引用の例外を超える複製・再利用には許諾が必要 | **候補探索にのみ使う**。検索は複製にあたらないため許諾申請が不要 |
| NDLデジタルコレクション（インターネット公開・保護期間満了） | 申請・許諾とも不要で自由利用可。転載元の明示が求められる | **採録する本文の調達元とする** |
| Wikisource 日本語版 | 投稿は CC BY-SA 4.0 / GFDL。PD資料には新たなライセンスを付さないと明記 | **使わない**。入力者の校訂部分にSA（継承）が及び、原文との切り分けが24語の作業に見合わない |
| 国書データベース（国文研） | 資料ごとにPD／CC／RS／All-Rights-Reserved を表示。書誌・典拠データは自由利用 | 翻刻本文の一括取得には不向きなため使わない |
| J-TEXTS 日本文学電子図書館 | **未確認**（サイトへ接続できず） | 判断保留。使わない |
| 新編国歌大観などの商用DB | — | 対象外 |

確認したページ:
[日文研サイトポリシー](https://www.nichibun.ac.jp/ja/information/policy/) ／
[日文研 和歌データベース](https://lapis.nichibun.ac.jp/waka/menu.html) ／
[NDL 複製・利用](https://www.ndl.go.jp/jp/use/reproduction/index.html) ／
[Wikisource:著作権](https://ja.wikisource.org/wiki/Wikisource:著作権) ／
[国書データベース 利用条件](https://kokusho.nijl.ac.jp/page/terms.html?ln=ja)

この方針により、コーパス原本をリポジトリへ取り込む工程自体が発生しないため、`.gitignore` での隔離も不要になる。

**副次的な効果**: 底本を1つ決めてそこから起こす形になるため、論点A-3（底本の統一）も同時に解決する。とくに万葉集は原文が万葉仮名で、訓読文の表記が校訂によって異なる（デプロイ済みの kv08-090「大君は千歳にまさむ」も底本によっては表記が変わり得る）。

### 2-1. 着手前に確定させること

- **底本の特定（未確認）**: 万葉集・古今集・新古今集それぞれについて、校訂者の著作権が満了しており、かつNDLで「インターネット公開（保護期間満了）」になっている版を特定する。`dl.ndl.go.jp` の書誌ページで公開範囲を直接確認すること。書名だけで判断しない。
- **底本の記録先**: 決めた底本と、各語がどの版に基づくかを `docs/SOURCE_EDITIONS.md`（新規）に記録する。語ごとのJSONにフィールドを足すとスキーマが広がるため、文書側で持つ。

### 2-2. 手順

1. 日文研DBで対象語を検索し、候補歌の所在（歌集・部立・作者）を `docs/waka-candidates.md` に手作業で控える。**この段階では本文を転記しない。** コーパスを取り込まないため `collect-waka-candidates.mjs` は作らない。
2. 人手レビュー（自動化しない）。採用条件は次の全てを満たすこと。
   - 対象語が掛詞の一方になっていない（基本形が一意に決まる）
   - 語義が当該語の `meanings` と一致する
   - 空欄が1つの句の内側に収まる
   - 作者と歌集が一次資料で確認できる
   - 採録する本文を、2-1で決めた底本のNDL公開画像から起こせる
3. `scripts/apply-waka.mjs`（新規）: 採用分を書いた入力表（`docs/waka-adoptions.json`）を読み、`example` / `cloze` / `source` / `translation` / `exampleForm` / `waka` を一括更新する。手入力は入力表に集約し、JSONの直接編集はしない（再実行可能にするため）。
4. `node scripts/check-data.mjs` で検証。



## 3. 音数リーク対策（`choiceSet`）

和歌の空欄は音数が確定するため、語義を知らなくても選択肢の音数で正答できる。段階2で塞ぐ。

- `static/mode-vocab.js` の `choiceSet` に、**和歌かつ文中問題のときだけ** 「見出し語のモーラ数が正解と±1の候補を優先し、足りなければ従来どおり補充する」段を追加する。
- 見出し語は仮名表記なので、`〜` 以降を落として小書き仮名を除けばモーラ数が求まる（`たえて〜打消` → `たえて` = 3）。
- **既存の契約に注意**: [check-context-choices.mjs:10](../scripts/check-context-choices.mjs:10) は `choiceSet` 内に `kind !== "meaning"` が現れないことを検査している。条件は `kind === "context"` の形で書く。
- 意味重複ガード（`isMeaningSafePair`）は従来どおり先に適用し、音数はその後の優先順位付けにのみ使う。安全な候補が3件に満たない場合は音数を無視して埋める（出題不能を避ける）。
- 新規 `scripts/check-waka-choices.mjs` で、和歌6語＋段階2で追加した語について「同音数の誤答が可能な限り選ばれる」ことを検査する。

## 4. 既存データの底本が記録されていない問題

利用条件の調査中に判明した別の問題として、**デプロイ済みの和歌6首と散文162件が、どのテキストから起こされたのか記録されていない**。`source` は作品名のみで、底本の情報がない。

- 段階2では、**新たに差し替える語について底本を `docs/SOURCE_EDITIONS.md` に記録する**（2-1）。
- 既存168語の遡及調査は範囲が大きいため段階2に含めない。段階3で扱うか、既存分は「底本不明」と明記して残すかを別途判断する。
- とくに kv08-090 は万葉集の訓読文で表記が底本依存のため、段階2で底本を決めた際に整合を確認する（5節の kv14-159 の校訂と同じ作業の中で処理できる）。

## 5. 段階1から持ち越した未確定事項

- **kv14-159「こしかた」**: 新古今出典だが本文の `つれは` / `なきそ` に濁点欠落の疑いがある。段階2で本文を校訂し、和歌か詞書かを確定させる。和歌なら `exampleForm: "waka"` へ移す。
- **kv03-031「かしらをおろす」/ kv08-093「いますがり」**: 歌集の詞書。散文のままで問題ないが、`source` が歌集名なので「詞書」と分かる表記にするか検討する。
- **`吾を`／`我を` の読み**: kv09-106 / kv10-116 を `わを` として確定済み。段階2で一次資料に当たる際、`あれを` でないことを併せて確認する。

## 6. 作業順序

1. 論点B〜Dを確定させる（Aは確定済み）。
2. 底本を特定する（2-1）。NDLで「インターネット公開（保護期間満了）」であることを書誌ページで確認し、`docs/SOURCE_EDITIONS.md` に記録する。
3. 24語を 1-a / 1-b / 1-c に区分し、日文研DBで候補を探して典拠を確定させる（本文は底本から起こす）。
4. 音数リーク対策（3節）を先に実装する。和歌が増える前に入れておけば、差し替えの都度リークを気にせずに済む。
5. 1-a を和歌化する（`apply-waka.mjs` で一括、`check-data.mjs` で検証）。
6. 1-b を散文の実出典へ差し替える。
7. kv14-159 の校訂（5節）。あわせて kv08-090 の表記を底本と照合する（4節）。
8. README のデータ説明と `WAKA_PHASE1_PLAN.md` §9 の既知の穴を更新する（音数リークを「対策済み」へ）。

4を5より先に置くのが重要。逆順だと、和歌が増えた状態でリークを含む出題が一時的に本番へ出る。
