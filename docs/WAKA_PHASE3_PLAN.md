# WAKA_PHASE3_PLAN — 例文の和歌化・案C 段階3 実装計画

> 前段: [WAKA_PHASE1_PLAN.md](WAKA_PHASE1_PLAN.md) / [WAKA_PHASE2_PLAN.md](WAKA_PHASE2_PLAN.md)。段階2は `8eb7ddc` でデプロイ済み。
> 状態: 実装済み（2026-08-24）。作成 2026-08-24。
> 段階3の目的: **段階1・2で積み残した整合性の穴を埋め、データの表記と記録を一貫させる**。和歌の語数を増やすことは主目的にしない。

## 0. 現況（実測・実装前）

| 指標 | 値 |
|---|---|
| 総語数 | 168語 |
| 和歌 | 13語（7.7%） |
| `exampleForm` | `waka` 13 / `prose` 13 / **未指定 142** |
| 非古典出典 | 5語（すべて段階2の1-c＝慣用表現群） |
| 底本が記録済み | 20語（段階2の19語＋kv08-090の照合） |

段階1・2で「和歌にできる語」はおおむね拾い切った。残る5語は句全体が慣用句で、実出典を当てると空欄の一意性が崩れやすい。**段階3で和歌率が大きく上がる見込みはない**（見込み 13語 → 14〜15語）。

## 1. 決定が必要な論点

| # | 論点 | 選択肢 | 推奨 |
|---|---|---|---|
| A | `source` の表記ゆれをどう解消するか | (A-1) 全和歌を「歌集名（巻・番号）」形式へ統一する ／ (A-2) 巻・番号を `waka.ref` へ分離し `source` は歌集名のみに戻す | **A-2**。`source` はUIで『』付きの見出しに出るため短い方がよい。番号はデータとして別に持つ方が後から底本を変えたときに追随しやすい |
| B | 1-c の5語をどうするか | (B-1) 実出典を当てて差し替える ／ (B-2) 作例と明示したうえで残す | **B-2優先で個別判断**。「えならず」「ものもおぼえず」は用例を当てやすいが、「〇〇といふも世の常なり」のような句型は作例の方が学習目的に合う |
| C | `exampleForm` 未指定142語をどうするか | (C-1) 全語へ `"prose"` を明示する ／ (C-2) 未指定＝散文の既定を維持する | **C-1**。「まだ判断していない」と「散文と判断した」が現状は区別できない。明示すれば段階4以降の見直し対象が一目で分かる |
| D | 既存149語の底本を遡及記録するか | (D-1) 全語を調査する ／ (D-2) 和歌と、表記が底本依存の語に限る ／ (D-3) 記録しない | **D-2**。全語調査は費用が大きすぎる。表記揺れが実害になるのは和歌と訓読文 |

## 2. 修正・実装項目

### 2-1. `source` の表記ゆれ解消（優先度: 高／論点A）

和歌13語で2つの書式が混在している。

- 段階1の6語: `古今和歌集` `万葉集` `新古今和歌集`（歌集名のみ）
- 段階2の7語: `万葉集（巻一・21番歌）` `後拾遺和歌集（巻十・哀傷・542番歌）`（巻・番号つき）

UIでは [mode-vocab.js:846](../static/mode-vocab.js:846) が `和歌　『{source}』` として見出しに出すため、**同じ画面遷移の中で見出しの長さが不揃いになる**。

対応:

1. `waka.ref` を追加する（例: `{"collection": "万葉集", "book": "巻一", "number": 21}` または表示用の文字列1本）。段階1計画で「底本を決めてから」と保留していた項目で、段階2で底本が確定したため着手できる。
2. `source` は歌集名のみへ統一する。
3. カード表示に `ref` を小さく添える（作者と同じ行、`.wakaAuthor` と同じ扱い）。
4. `check-data.mjs` に「`exampleForm === "waka"` なら `source` に括弧を含まない」検査を追加し、再発を防ぐ。

### 2-2. `exampleForm` の全語明示（優先度: 中／論点C）

- 未指定142語へ `"prose"` を付与する。機械的な一括変更なので `scripts/` に一度きりのスクリプトを置くか、`apply-waka.mjs` の入力表経由で行う。
- 付与後、`check-data.mjs` の `exampleForm` を**必須**へ格上げする（現在は省略可）。
- 効果: 「散文と判断済み」と「未検討」が区別でき、段階4以降で和歌化候補を探す際の対象が明確になる。

### 2-3. 音数リーク対策の実効性向上（優先度: 中）

段階2のブラウザ確認で、kv12-138「いも」の設問の選択肢が「いちのひと(5音) / ただびと(4音) / いも(2音) / これ(2音)」となり、**同音数の誤答が1件しか入らなかった**。

原因を実測で切り分けた結果は次のとおり。

- モーラ数だけで見れば、和歌13語すべてで同音数±1の候補が**3語以上**ある（最少はkv03-026とkv09-106の3語）。
- 不足しているのは、**意味重複ガード `isMeaningSafePair` を通過したあと**の候補。第12セットは親族・人称語が集中していて意味が近く、安全な候補が3件に満たずフォールバックしている。

つまり「モーラ候補が足りない」のではなく「**同一セット内に限定していること**」が制約になっている。

対応:

- [mode-vocab.js:301](../static/mode-vocab.js:301) の候補補充が `kind === "meaning"` のときだけセット横断（`reviewPoolEntries`）を参照している。これを**和歌の文中問題にも広げる**ことを検討する。
- ただし文中問題の正解は見出し語なので、他セットの語を混ぜると「そのセットで学んでいない語」が選択肢に出る。学習体験への影響があるため、**先に方針を決めてから実装する**。代案は、和歌を配置するセットを選ぶ段階で語彙の意味的な近さを避けること（データ側の対処）。
- どちらを採るにせよ、`check-waka-choices.mjs` に「同音数の誤答が最低1件は入る」等の実効性の下限を検査として置く。

### 2-4. 1-c の慣用表現5語（優先度: 中／論点B）

| 語ID | 見出し語 | 所見 |
|---|---|---|
| kv05-060 | えならず | 用例を当てやすい（源氏・枕草子に多い）。実出典化を試す |
| kv05-054 | ものもおぼえず | 同上 |
| kv05-052 | われ（かひとか）にもあらず | 句型のまま出る用例は限られる。要調査 |
| kv04-045 | さるべきにや（ありけむ） | 同上 |
| kv05-058 | 〇〇といふも世の常なり | 見出し語自体が句型のテンプレート。**作例のまま残す方が妥当** |

- 実出典化するものは段階2と同じ手順（日文研DBで所在確認 → NDL保護期間満了資料から本文を起こす → `waka-adoptions.json` 経由で反映）。
- 作例のまま残すものは、`source` を「出典未詳」ではなく**作例と分かる表記**へ改める（例: `学習用作例`）。「出典未詳」は「出典があるはずだが特定できていない」と読めてしまい、実態と合わない。

### 2-5. 底本の遡及記録（優先度: 低／論点D）

- 対象は和歌13語のうち段階1の6語（底本未記録）と、訓読文・変体漢文を含む語。
- `docs/SOURCE_EDITIONS.md` の「語ごとの対応」へ追記する。
- 段階1の6語は本文がすでに公開されているため、**底本と字面が食い違っていた場合は本文を訂正する**必要がある。とくに kv08-090 は段階2で『万葉集古義』二と照合済みだが、他5語は未照合。

### 2-6. 詞書3語の `source` 表記（優先度: 低）

kv03-031「かしらをおろす」・kv08-093「いますがり」・kv12-137「おとうと」は歌集の詞書で、本文は散文。`source` が歌集名のため、和歌と紛らわしい。「古今和歌集（詞書）」のように明示するか検討する。2-1で `source` の書式を触るので同時に行う。

### 2-7. `waka.rhetoric`（掛詞・枕詞）の表示（優先度: 低）

- 段階1で予約したまま未使用のフィールド。`notes` と役割が重複するため、**先に分担を決める**。
- 提案: `notes` は語義・語法の説明に限り、`rhetoric` は当該歌の修辞に限る。両方に同じ内容を書かない。
- 対象13語のうち、掛詞・枕詞が明確なものだけに付ける（kv04-043「玉の緒」の「ながらへば」など）。全語に無理に付けない。

## 3. 作業順序

1. 論点A〜Dを確定させる。
2. 2-1（`source` 統一と `waka.ref` 追加）。データ・表示・検証をまとめて変更する。
3. 2-6（詞書3語の表記）。2-1と同じファイルを触るため同時に行う。
4. 2-2（`exampleForm` の全語明示と必須化）。
5. 2-5（底本の遡及記録）。ここで本文の訂正が発生したら 2-1 の結果へ反映する。
6. 2-4（1-c の5語）。
7. 2-3（音数リーク対策の実効性）。方針決定に時間がかかる可能性があるため最後に置く。
8. 2-7（`rhetoric`）。任意。

2→3→4 の順が重要。逆順だと `exampleForm` 必須化のあとに `source` を触ることになり、検証を2度通す手間が増える。

## 4. 検証

- `node scripts/check-data.mjs` / `check-waka-data.mjs` / `check-waka-choices.mjs` / `check-waka-display.mjs`
- `node scripts/check-context-choices.mjs` / `node scripts/check-srs.cjs` / `node --check static/mode-vocab.js`
- 2-1 で `waka.ref` の表示を足すため、**ブラウザ確認が必要**。第12セットの和歌カードと文中問題で、`ref` が作者と並んで崩れずに出ること、320px幅で横スクロールがないことを確認する。
- 2-3 を実装する場合は、選択肢に他セットの語が混ざる挙動を実画面で確認する。
- 公開検証: デプロイ後に公開URLから `data/*.json` と `static/mode-vocab.js` を取得し、`source` の書式が統一されていることを確認する。

## 5. 段階3では行わないこと

- 和歌の語数を積極的に増やすこと。和歌にできる語は段階1・2でおおむね拾い切っており、無理に増やすと語義と歌意の対応が崩れる。
- 既存168語すべての底本調査（論点D-1）。費用に対して得るものが小さい。
- `apply-waka.mjs` の汎用化。現状の「入力表を読んで一括更新する」形で足りている。

## 6. 実装結果

- **A-2を採用**。和歌13語の `source` を歌集名だけに統一し、`waka.ref` に `collection`・`book`・`number` を追加した。`check-data.mjs` と `check-waka-data.mjs` で両者の一致と括弧なしを検査し、カードには作者と出典箇所を併記する。
- **B-2を採用**。`kv04-045`・`kv05-052`・`kv05-054`・`kv05-058`・`kv05-060` は本文を維持し、`source: "学習用作例"` とした。未確認の古典出典は付与していない。
- **C-1を採用**。全168語に `exampleForm` を明示した。内訳は和歌13語、散文155語。既存の未指定142語のうち、先に個別表記を決めた7語を除く135語は `scripts/mark-prose.mjs` で `prose` を付与した。
- **D-2を採用**。和歌13語の底本・歌番号を `docs/SOURCE_EDITIONS.md` に追記し、詞書3語と作例5語の扱いも記録した。
- 文中問題の選択肢は、未習語が混ざる学習上の副作用を避けるため**同一セット内の候補を維持**した。`check-waka-choices.mjs` は和歌ごとに同一セット内の同音数帯かつ意味重複なしの候補が最低1件あることを検査する。セット横断の選択肢は今回採用していない。
- `waka.rhetoric` は任意項目のまま追加しなかった。語義・語法の `notes` と歌の修辞を混在させない方針だけを残し、確実な対象がまとまった段階で別途扱う。
